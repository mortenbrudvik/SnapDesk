# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SnapDesk is a macOS menu-bar workspace launcher (Swift 6, AppKit + SwiftUI, Accessibility API, `LSUIElement`). Capture records the windows open right now — app, title, display, frame relative to that display's visible frame, minimized and zoomed state, in CoreGraphics front-to-back order — into a `.snapdesk` JSON document. Restore launches or reuses those apps and puts their windows back. An editor window edits a document before saving or launching it, the status menu keeps recents, and Capture and Editor have global hotkeys. Not sandboxed; the App Sandbox blocks the AX calls it needs.

## Commands

The Xcode project is generated by XcodeGen from `project.yml`; `project.pbxproj` is committed. Regenerate after adding, removing, or moving any source or test file, or the file is not in the build:

```bash
xcodegen generate                      # /opt/homebrew/bin/xcodegen if Homebrew is not on PATH
```

Build and test (the `SnapDesk` scheme is committed under `xcshareddata` and includes the test target):

```bash
xcodebuild -scheme SnapDesk -destination 'platform=macOS' build
xcodebuild -scheme SnapDesk -destination 'platform=macOS' test
xcodebuild -scheme SnapDesk -destination 'platform=macOS' test -only-testing:SnapDeskTests/WindowMatcherTests
xcodebuild -scheme SnapDesk -destination 'platform=macOS' test -only-testing:SnapDeskTests/WindowMatcherTests/testExactTitleClaimsDocsNotGitHub
```

Add `-derivedDataPath <dir>` to keep build products out of `~/Library/Developer/Xcode/DerivedData`. `xcodebuild` output is verbose; filter for `error:`, `warning:`, `Executed`, and `TEST SUCCEEDED|FAILED` — then read the next section before treating a green run as a run that tested anything.

Both configurations sign with the maintainer's Developer ID (`project.yml`), which is deliberate for Debug too — see below. On a machine without that certificate, append `CODE_SIGN_IDENTITY=-` to build Debug ad-hoc (verified); Release additionally sets hardened runtime and `--timestamp`, so it needs `CODE_SIGN_IDENTITY=- ENABLE_HARDENED_RUNTIME=NO OTHER_CODE_SIGN_FLAGS=`. Version numbers live in `project.yml` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`).

The app icon is generated rather than hand-drawn, so it has readable source and can be adjusted:

```bash
swift Tools/IconRenderer/main.swift SnapDesk/App/Assets.xcassets/AppIcon.appiconset
xcodegen generate    # only if the set of files changed; the PNGs themselves are already referenced
```

The geometry lives in the `Design` enum at the top of that file. Two details there are load-bearing
and were arrived at by looking at the result: renders at or below 40px use wider gaps, solid white
panes and pixel-snapped edges, and renders at or below 32px drop the shadow — a blur that lifts the
icon at 512 is a grey halo two pixels wide at 16, which is the size this icon is seen at most.

Reading the app's logs: `log` is a zsh builtin, so use the full path, and the info-level lines (the launch summary, the captured-window count, the per-restore summary) need `--info`:

```bash
/usr/bin/log show --info --predicate 'subsystem == "com.brudvik.snapdesk"' --last 10m
```

Categories are declared in `Log.swift`: `app`, `ax`, `hotkeys`, `settings`, `launch`, `capture`, `editor`, `displays`.

## Testing and Accessibility

Tests run inside the real app as host (`TEST_HOST`), so `AppDelegate.applicationDidFinishLaunching` returns early when `XCTestConfigurationFilePath` is set. Keep it that way: otherwise every test run installs a status item, registers the global hotkeys, and can put the Accessibility prompt on screen.

`AXWindowTests` is the only coverage of `AXWindow`'s live Accessibility calls — the pure `isZoomed(frame:on:)` inference is also pinned in `CaptureServiceTests` — and it drives real AX calls against `NSWindow`s the test host creates and owns. **Every case except the two role guards needs a TCC grant** (they are counted, not listed, so the number is not repeated here to go stale). Measured: with no grant the test host's own windows are not vended over Accessibility, and those cases skip rather than fail. The skip message reports what TCC says, which is the difference between "never granted" and "granted but not applying" — those need opposite repairs.

One case is deliberately *not* skippable: `axWindow(for:)` does the raw `kAXWindows` read first, and once that vends the window, a wrapper that then answers nothing is a failure. Before that, a regression in `AXWindow.windows(pid:)` skipped the whole file and the run still reported success.

That file is developer-machine-only. Where no window server answers AX, enumerating our own windows takes the test host down instead of returning an error, so a CI runner added later must pass `-skip-testing:SnapDeskTests/AXWindowTests`. There is no CI in this repo today.

A grant is keyed to the code signature, and an ad-hoc signature has no designated requirement beyond its cdhash — which changes on every rebuild — so an ad-hoc Debug build dropped the grant every time it was rebuilt. That is why `project.yml` signs *Debug* with `Developer ID Application: Morten Brudvik (3GS65HFAFH)` (the only identity on the maintainer's machine): a certificate gives the signature a stable requirement, so the grant survives a rebuild. On a machine without that certificate, `CODE_SIGN_IDENTITY=-` builds ad-hoc again — and then the grant has to be removed and re-added after every build. What gets granted is the built `SnapDesk.app` that hosts the tests, under System Settings › Privacy & Security › Accessibility — not Xcode and not the terminal.

**Read the skip count, not the exit status.** The guards are `XCTSkip`, and a skipped test is not a failure: a run without the grant skips every `AXWindowTests` case except the two role guards and still prints `** TEST SUCCEEDED **` — the whole Accessibility layer goes untested and nothing says so. Set the variable below to turn those skips into failures, and use it for any change to `AXWindow`:

```bash
SNAPDESK_REQUIRE_AX=1 TEST_RUNNER_SNAPDESK_REQUIRE_AX=1 \
  xcodebuild -scheme SnapDesk -destination 'platform=macOS' test
```

Both spellings are set because the test host is launched by `xcodebuild`, not by the shell, and `AXWindowTests.accessibilityIsRequired` reads either. **The `TEST_RUNNER_` one is the one that works.** Measured on this project: with the environment simulated as ungranted, a plain `SNAPDESK_REQUIRE_AX=1 xcodebuild … test` still printed `** TEST SUCCEEDED **` with the whole file skipped — the variable never reached the test host — while `TEST_RUNNER_SNAPDESK_REQUIRE_AX=1` on the same invocation produced `** TEST FAILED **`, 0 skipped. `xcodebuild` forwards only `TEST_RUNNER_`-prefixed variables into the host process (stripping the prefix); the unprefixed spelling is there for a scheme or test-plan entry, not for the command line. Do not drop it from the command above.

The test target is deliberately not parallelizable (`parallelizable = "NO"` in the shared scheme). `AXWindowTests`, `EditorWindowTests` and `StatusItemControllerTests` all drive real windows and a real status item inside the one shared host, and `HotkeyNameTests` snapshots and rewrites the host's whole persistent domain; running them concurrently makes them interfere. Do not turn it on for speed.

Nothing else in the suite needs the grant: `LaunchServiceTests` runs whole restores against hand-written fakes and a `RestoreClock` whose sleeps are instant and whose `now` is virtual, so the 8-second window wait and the 4-second correction window cost nothing — and a test can still charge the clock for a slow Accessibility read (`ScriptedClock.advance(by:)`) to exercise the wall-clock ceiling.

## Architecture

Two paths meet in `WorkspaceDocument`, the `.snapdesk` file's in-memory form: capture writes one, restore reads one.

- **Capture.** `CaptureService.capture()` returns a `CaptureOutcome`: the document, and a `CaptureReport` of what it could not record. It asks `RunningAppSourcing` for the running apps, skips SnapDesk itself, anything not `.regular`, and anything with no bundle identifier (restore matches on it, so such a slot could never be filled), and asks `AXCapturing` for each pid's windows. That call *throws* rather than answering `[]` when the list could not be read — an app that did not answer within the AX timeout used to vanish from the workspace silently — and a window whose frame or minimized state could not be read is skipped and counted. Each survivor becomes a `CaptureCandidate` for `CaptureFilter.isEligible`, which drops a few subroles, anything under 8pt, and the chromeless-`AXStandardWindow` shape that an Open/Save panel has; the role is guarded once, by `AXWindow.init?`. The editor shows the report on top of the captured document. `CaptureOrdering.sortedIndices` then sorts survivors by the front-to-back order `CGWindowListOrdering` reports, with minimized windows, windows with no CoreGraphics id, and windows on another Space trailing in their original order. Each window is stamped with the display holding its centre and stored as a frame *relative to that display's visible frame* (`FramePlacement.relative`); a window that matches no display is recorded against the primary one rather than dropped.
- **Restore.** `AppDelegate.launch` validates, then hands the document to `LaunchService.launch`, which serialises runs on `LaunchGate`. `LaunchPlanner.plan` groups slots by bundle id and decides launch-vs-reuse per group: under `moveExistingWindows` — or for an app whose Info.plist sets `LSMultipleInstancesProhibited`, which forces that mode — a running app is reused and only a group's first slot launches at all, otherwise every slot launches a new instance. Launches go through `ApplicationLaunching` under `defaultLaunchTimeout` (10s), which bounds the *wait* and not merely the error: the open runs as its own task and is abandoned at the deadline, because `NSWorkspace.openApplication` does not observe cancellation. Then the claim loop: poll `WindowCatalog` every `windowPollInterval` (100ms), bounded both by a poll count and by a wall-clock deadline (`defaultWindowTimeout`, 8s) — the count keeps the wait the same length under any clock, the deadline holds when each poll's Accessibility reads are slow. It settles every exact title first (`WindowMatcher.exactTitles`) and hands out leftovers early only to the slots of an app that has already vended as many windows as the workspace expects (`finishedBundles`) — and, once the budget is spent, to every slot still waiting, which then fails as `.noWindow`, or `.windowsUnreadable` if that app never answered a read at all. Windows belonging to a process that was already running when a *new instance* was launched are filtered out of the pool by pid, so "move existing windows" off really does leave the user's own windows alone. Placement runs in `LaunchPlanner.placeOrder` — descending, so slot 0 is placed last and ends on top — through `targetFrame` (`DisplayMap.resolve` → `FramePlacement.restore` → `clamp`) and `WindowPlacing`, which answers a `PlacementOutcome` rather than a Bool: a window that vanished, a refused write and a saved zoom that would not take are three different failures. `WindowPlacement.apply` is the ordering that matters: un-minimize, wait for the state to actually flip, un-zoom, write the frame, re-zoom under a read-back loop, re-minimize. Finally `correctProvisionalClaims` spends `correctionWindow` (4s) watching for the window a slot was actually named after, and swaps it in if it turns up.
- **Seams.** `ApplicationLaunching`, `RunningApplicationQuerying`, `WindowCatalog`, `WindowPlacing`, `RestoreClock` and `PlaceableWindow` all have a production conformance in `LaunchService.swift` and a fake in the tests; `DelayRunning` does the same for the HUD's auto-dismiss, `AXCapturing` for capture, and `EditorPrompting` for the editor's modals. `AppDelegate.Dependencies` is the same idea one level up — recents, capture, `WorkspaceRestoring`, `LaunchHUDPresenting`, the trust check and the alert presenter — so the launch chain, the queue and the open-before-launch buffer are testable without moving a window or raising a modal. Extend these rather than reaching for `NSWorkspace` in new code.
- **Geometry.** `AXWindow` is the only file that handles Accessibility-space (top-left origin) rects; everything it exposes is Cocoa space. `ScreenGeometry` flips about the **primary** display (`NSScreen.screens[0]`, never `NSScreen.main`) and is otherwise pure — every lookup is a function of the `[LiveDisplay]` it is handed. `LiveDisplay` is a value snapshot of an `NSScreen`, which cannot be fabricated, so multi-display logic is testable. `DisplayMap.match` falls back in descending confidence: same UUID, then same localized name, then closest `visibleFrame` size — and that last one is a guess that always answers, so `resolve` logs when a window lands on a substitute screen.
- **UI.** `AppDelegate` owns everything: `StatusItemController` (menu, recents, the Accessibility status row), `HotkeyCenter` (Capture and Editor, via KeyboardShortcuts/Carbon), `EditorWindowController` + `EditorSession`, `SettingsWindowController`, and `LaunchHUDController`. `AboutPanel` is the exception to that ownership: it is AppKit's standard About panel, which owns itself, so `StatusItemController` calls it directly through a default closure — the same shape as `accessibilityTrusted` beside it. It passes only the credits; name, version and copyright come from the bundle, so they cannot drift from `project.yml`. Restores are also chained at this level (`launchChain` + `LaunchQueue`), on top of `LaunchGate`: the HUD reset in `present(title:)` happens outside the service's gate, so without the chain a queued restore would wipe a running one's rows.

### Invariants worth knowing before editing

- **A failure the user cannot see is the bug.** Restore reports `.placed(PlacementNote)` — the note says whether the slot settled for a window it is not named after, and whether it went to a substitute display — and `SlotFailure` distinguishes `.noWindow`, `.windowsUnreadable`, `.windowGone`, `.couldNotPosition` and `.stateNotRestored`. Capture reports a `CaptureReport`. Both exist because every one of those cases used to read as a clean restore or a complete capture.

The measurements behind the restore design — why discovery polls rather than
using `AXWindowCreated`, why the settle decision is revocable, why no signal
identifies a start-page window, and why the AX messaging timeout is 0.5s — are
recorded in `docs/decisions/window-discovery.md`. Read it before changing the
claim loop or the timeouts; several of those conclusions are counter-intuitive
and were expensive to establish.

- **There is no `AXZoomed` attribute.** It exists in no macOS framework: reading, writing or asking whether it is settable returns `kAXErrorAttributeUnsupported`, and the string appears nowhere in the dyld shared cache. Zoom is *inferred* from the frame against the display's visible frame (`AXWindow.isZoomed(frame:on:)`, 2pt tolerance) and changed only by pressing `kAXZoomButtonAttribute` — a toggle AppKit aims with its own frame test, so a press has no direction of its own and `.success` never means the window ended up zoomed. Read the state back (`WindowPlacement.ensureZoomed` presses at most twice and re-reads between).
- **AX writes are asynchronous.** `setMinimized` returning `.success` is the write being accepted, not the window leaving the Dock — and a frame written to a window still in the Dock is swallowed while AX reports success for it. Every state change that something later depends on is polled until it flips (`WindowPlacement.settled`).
- **A failed AX read must never be persisted as `false`.** `minimizedState` is nil for a read that failed and false for a window that is simply not minimized; capture uses it and skips the window when it is nil, because a wrong value goes to disk and every later restore reproduces it. `isMinimized`/`isZoomed` collapse the two and are only for a decision made now and discarded.
- **`AXWindow.messagingTimeout` is 0.5s and must not be tightened.** A timed-out read returns `.cannotComplete`, which is indistinguishable from "this app has no windows yet", so an over-tight timeout feeds the wrong branch of the wait-or-settle decision in `LaunchService`. Legitimate reads were measured at 257–261ms with several apps launching at once, which is exactly what a restore does.
- **Window discovery polls deliberately.** `AXWindowCreated` exists and fires reliably, but an observer can only arm once the app's AX server answers — which `isFinishedLaunching` marks, 11–658 ms *before* the first window in 12 measured launches — and there is no replay. In 13 of 13 in-callback checks the window was already in `kAXWindows`, and some apps (Calculator, Dictionary) never emit for their launch window at all, so an event-driven path finds a just-launched window strictly later than a read, or not at all. See the comment on `LaunchService.windowPollInterval` before "improving" this.
- **"Has this app finished opening its windows" is not knowable.** The count the workspace expects is the signal, and the decision is made *revocable* instead: a slot that settled for a window it is not named after is recorded as provisional and swapped for its own window if that arrives inside `correctionWindow`.
- **`LaunchPlanner.placeOrder` is descending on purpose.** Placing a window raises it, so back-to-front placement leaves slot 0 on top. Replacing it with `0..<count` inverts every restored stack while every placement assertion still passes.
- **Swift 6 with `SWIFT_STRICT_CONCURRENCY: complete`.** Everything with state is `@MainActor`. Some AX/Carbon constants are declared `extern CFStringRef` and imported as mutable globals that Swift 6 rejects as shared mutable state; use their string values instead (`"AXTrustedCheckOptionPrompt"` in `AccessibilityAuth`). `"AXEnhancedUserInterface"` in `AXWindow` is a literal for a different reason: the attribute is undocumented and the SDK declares no constant for it at all.
- **`WorkspaceDocument.validate()` runs on both decode and encode.** The editor must not be able to write a file this build then refuses to reopen, and the editor's in-memory Launch has no file in between. That check is no longer a convention: `LaunchService.launch` takes a `ValidatedWorkspace`, whose only source is `WorkspaceDocument.validated()`, so nothing can reach the placement code unchecked. `decode` probes the version alone first, so a file from a future schema is explained rather than reported as a parse error.
- **KeyboardShortcuts is pinned to `minorVersion: "2.4.0"`, not a major range.** Its `Shortcut` Codable form is persisted in UserDefaults, and it is *synthesised* from stored properties the library is free to rename in any release — there is no `CodingKeys`, so the storage format is not something it has promised to keep. A silent change leaves every hotkey unbound with no error. `HotkeyNameTests` sets a shortcut and reads it back through the library, which is the round trip that would break — but only after an open range has already let the change in, so the range is the place to hold it.

### System side effects

- **Not sandboxed** (`SnapDesk.entitlements` sets `com.apple.security.app-sandbox` to false); the App Sandbox blocks the AX calls. `AXWindow.cgWindowID` also resolves the private `_AXUIElementGetWindow` SPI with `dlsym`, degrading to a title-based identity if it ever disappears — not App Store safe either way.
- **Restore moves other apps' windows and launches apps.** Running the app, or exercising the restore path by hand, rearranges the developer's own desktop; `AXWindowTests` likewise puts real windows on screen for the length of the run.
- **`RecentsStore` writes `recentsBookmarks` and `recentsPaths` to `UserDefaults.standard`**, which under `TEST_HOST` is the shipping app's own domain. Tests that touch it build a throwaway suite and remove it in teardown (`RecentsStoreTests.scratchDefaults`, and the same pattern in `EditorSessionTests`, `EditorWindowTests`, `StatusItemControllerTests`). `HotkeyNameTests` cannot: KeyboardShortcuts reads `UserDefaults.standard` itself, so it snapshots the app's whole persistent domain in `setUp` and writes it back in `tearDown`.
- **Launch at login is `SMAppService.mainApp`**, with nothing mirrored into defaults — the user can remove the login item in System Settings while SnapDesk is not running. `register()` can succeed and still report `.requiresApproval`, which the Settings pane surfaces. `AppSettings.launchAtLogin` reassigns itself from inside a method called by its own `didSet`; the `isApplyingLoginItem` guard is what stops the recursion.
- **`LSUIElement`**: no Dock icon and no app menu, so the SwiftUI `Settings` scene is inert and every window is built in AppKit by `AppDelegate`. Info.plist exports the `com.brudvik.snapdesk.workspace` UTI for the `.snapdesk` extension (deliberately not the bundle identifier — LaunchServices registers both), named once in `WorkspaceFileType` and pinned against the bundle's own declaration by `WorkspaceFileTypeTests`. Double-clicking a workspace reaches `application(_:open:)` — which AppKit delivers *inside* `finishLaunching`, before `applicationDidFinishLaunching`, so those URLs are buffered and drained by `completeLaunch()` rather than acted on while the status item and hot keys do not exist yet.
- **The app icon is seen small, and mostly outside the app.** With no Dock icon, where it appears is the System Settings › Privacy & Security › Accessibility list, Login Items, and Finder — 16 to 32pt. `BundleTests` asserts the bundle names the asset and that every one of those sizes is present, because a dropped or renamed catalog compiles cleanly and simply shows a blank page there.
- **`AccessibilityAuth.relaunch()`** asks to quit and leaves a flag; `AppDelegate.applicationShouldTerminate` starts the `/bin/sh` helper through `armRelaunchHelperIfPending()` once every veto has had its turn. The helper waits for this pid to exit and then `open`s the bundle — `open` on a running bundle only activates it, and only a fresh process picks up a new grant. It must not be started earlier: spawned before the quit was granted, it stayed armed for its ten-second ceiling after a *vetoed* quit, and a real ⌘Q inside that window brought the app straight back. A helper that cannot be started vetoes the quit, because the app would otherwise vanish and not return. `isEffectivelyTrusted` probes a real AX read against *another* application, because `AXIsProcessTrusted` can answer yes while every call still returns `.apiDisabled` until that relaunch.
- **`HotkeyCenter` logs what each command is configured to use, not what registered.** KeyboardShortcuts swallows Carbon registration failures (it prints to stdout, which an `LSUIElement` app discards) and still reports the shortcut as set, so a combination another app already owns logs the same line and then never fires.
